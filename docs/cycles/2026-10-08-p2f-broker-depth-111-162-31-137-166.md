## WHAT WAS IMPLEMENTED
- **Fake broker environment** (Phase 111,
  `tests/fake_broker.py`, test-support only — the shipped
  app never imports it): a stateful FakeBrokerSite with
  the real broker lifecycle (listing present → opt-out
  POST → pending → processed → removed), its own search
  page and a DDG-shaped results builder driven by the
  same listing state, switchable failure modes (down /
  renamed form fields / persist-after-opt-out /
  challenge page), and form shapes for the generic
  playbook plus Spokeo's hand-mapped one. Only the
  transport is faked, at the two seams the codebase
  designates; everything above transport runs unmodified.
- **E2E regression harness** (Phase 162,
  `tests/test_fake_broker_e2e.py`): TestFakeBrokerEnvironment
  (8 tests of the fake itself, including parsing its
  pages with the real FormParser) and
  TestFakeBrokerWorkflowDb (8 DB tests driving API →
  cases → engine.process_case / worker.run_once →
  verify.verify_case): Spokeo and generic CheckPeople
  happy paths to verified_removed with verification_checks
  asserted in order, the worker claim path with the real
  executor, and pinned honest negatives — persist (never
  verified_removed), down (blocked/unreachable, trail
  [http, relay, browser(skipped: on_server)]), renamed
  (blocked/form_not_fillable with ZERO submissions at the
  site), challenge (needs_human/captcha). Fixture
  identities are per-test/per-run unique because
  identifiers are globally unique by lookup hash (409 by
  design).
- **Workflow versioning** (Phase 31, migration
  `0016_attempt_workflow_version.sql`): attempts gain a
  nullable workflow_version (+ index), stamped at the
  single INSERT site in `remediation/engine.py` from the
  case's broker at creation — worker runs, retries and
  failure parking all covered; pre-0016 rows stay NULL
  (honestly unknown, never backfilled). Surfaces: the new
  case-detail endpoint `GET /api/remediation/cases/<id>`
  (case + attempts with versions; anon → 401, foreign
  user → house 404) and the admin metrics aggregate
  `remediation_attempts_by_workflow_version`.
- **Probe classification matrix** (Phase 137,
  `TestVerifyClassificationMatrix` in
  tests/test_verify_sources.py): an executable
  evidence→verdict table pinning the gaps — timeouts →
  unknown, blocked statuses (401/403/429/500/503) →
  unknown, unexpected content → unknown on both methods,
  SSRF-refusal of the verify URL → unknown with the
  fetcher never called; probe-side precedence pinned
  (CAPTCHA/login blockers beat a fillable form, http_500
  reason, non-dict probe → probe_error). Ambiguous
  evidence is `unknown`, never found/removed.
- **Secure browser context** (Phase 166,
  `browser_probe.py`): a domain allowlist built from the
  broker/verify data (opt-out, alt, listing hosts) plus a
  local config list (`LEAKGUARD_PROBE_EXTRA_DOMAINS` env
  + `probe_domains.txt`); matching is domain-or-subdomain
  (suffix lookalikes refused). Enforcement: pre-flight
  refusal before Playwright is imported, a context.route
  guard aborting + recording any off-list request
  (navigation, redirect hop, subresource), and a
  landed-URL check; refusals land in the result's
  `refused` list + blockers. The script stays
  stdlib-only; the server stays browser-free.

## WHAT WAS DELIBERATELY NOT IMPLEMENTED
- A raw-socket / loopback-HTTP fake broker: production
  SSRF policy is never weakened for tests (the standing
  guardrail). The honest deliverable sits at the
  transport seam; socket-level SSRF plumbing is already
  proven by tests/test_ssrf_pinning.py. A harness test
  proves a literal loopback/private URL is still refused
  while the fake transport is active.
- Real-Playwright execution of the Phase 166 flows:
  Playwright is absent from this environment and CI by
  design; probe-flow tests inject a faithful fake
  `playwright` module into sys.modules while the guard
  code under test is the real code, and the allowlist
  functions are tested as pure functions.
- Admin-UI rendering for the version aggregate (JSON
  surface only, like several existing metrics blocks).
- Backfilling workflow_version on pre-0016 attempts: the
  version those attempts ran under is genuinely unknown;
  NULL says so.

## KNOWN LIMITATIONS
The relay-reader leg inside the harness is a
re-implementation (production's relay is a third-party
internet service a test cannot call); it honours the
production contract using the agent's own parser, and
the substitution is stated in the fake's docstring —
the http and verify legs are fully real. Phase 166's
browser flows are proven against a faithful fake
playwright module, not a real browser (environment
limit, recorded). Case-detail is API-only; the SPA does
not yet render an attempts view (the data surface the
phase required exists and is gated correctly).

## RISKS
The fake broker is a model of broker behavior, not the
brokers: a playbook can pass the harness and still meet
a changed real site — that is what the Phase 137 matrix
(ambiguous → unknown) and the source sweep exist to
catch honestly rather than paper over. The allowlist is
derived from broker data at probe start; a broker that
moves its opt-out to a new domain needs the data (or
the local config list) updated before the local probe
will follow it — by design.
