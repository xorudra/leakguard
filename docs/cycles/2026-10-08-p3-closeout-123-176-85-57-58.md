## SECURITY CONTROLS
The report route is session-only (a read-only Bearer API
token never suffices for a personal document); every
query is owner-scoped by the session user id through the
existing services, so cross-account data cannot appear
(the isolation property is test-pinned). All interpolated
values are HTML-escaped; the document carries no scripts
and no external assets. The response flows through the
app's single _send choke point, so the Phase 67
`Cache-Control: no-store` policy covers it — asserted on
the wire by the new tests. No new surface for 123/176
(verification and records only).

## PRIVACY CONTROLS
The report is masked-only BY CONSTRUCTION: the builder
imports no vault key material, calls no decrypt function,
and reads identifiers/account email exclusively in their
stored masked forms — the deliberate difference from
accounts/privacy.py's password-gated plaintext export,
whose decryption path the report does not reuse. The
plaintext-absence property is test-pinned (seeded value
never appears; its mask does). Nothing is persisted,
scheduled, or emailed: the document exists only in the
response. No PII was added to any doc written this cycle
(the review cites counts, file paths, and shapes only).
